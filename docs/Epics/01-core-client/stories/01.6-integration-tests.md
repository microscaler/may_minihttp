# Story 01.6: Integration Tests with Mock Server

## Description

Write comprehensive integration tests using a mock may_minihttp server. Tests verify the full request/response lifecycle: connection, header passing, JSON serialization/deserialization, status code handling, error cases, and connection reuse. Use may_minihttp's existing test infrastructure (in-memory handler or local TCP server).

## Functional Requirements

- [ ] `may_minihttp/tests/client_integration.rs` (or `tests/client/` directory) contains integration tests
- [ ] Tests use a real may_minihttp server (TCP) or in-memory test server if available
- [ ] Test categories:
  - [ ] GET request with no body
  - [ ] POST request with JSON body
  - [ ] Custom headers (single and multiple)
  - [ ] Status code handling (200, 404, 500)
  - [ ] JSON serialization round-trip
  - [ ] Connection reuse (multiple requests on same client)
  - [ ] Default headers applied to all requests
  - [ ] Request-specific headers override defaults
  - [ ] Invalid JSON in response triggers deserialization error
  - [ ] Connection failure returns `Error::ConnectionFailed`
  - [ ] HTTP error status returns `Error::HttpError`
  - [x] HTTPS request/response using rustls and a deterministic local CA

## Non-Functional Requirements

- [ ] Tests run in < 10 seconds total
- [ ] Tests are deterministic (no randomness, no network dependency beyond local)
- [ ] Tests use `#[test]` functions, no async (may coroutines are sync in this context)
- [ ] Each test is independent — no shared mutable state between tests
- [ ] Tests use `may_minihttp::HttpServer` to create a mock server

## Acceptance Criteria

1. All 12 test scenarios pass
2. Tests cover happy path and error paths
3. Tests verify error types are correct (not just that an error occurred)
4. Tests verify connection reuse (count connections, not request count)
5. Tests verify header case-insensitivity
6. Tests verify body size limit enforcement

## Definition of Done

- [ ] `cargo test --features client` passes with all integration tests
- [ ] Test coverage >= 80% for client module
- [ ] Tests run in < 10 seconds
- [ ] Tests are deterministic and reproducible
- [ ] Test infrastructure is documented in README
- [ ] Commit message: `feat(client): add integration tests with mock server`

// Test fixture: mock server handler
struct TestHandler;

impl HttpService for TestHandler {
    fn call(&mut self, req: Request, res: &mut Response) {
        match (req.method(), req.path()) {
            ("GET", "/ok") => {
                res.status_code(200, "OK");
                res.body("Hello, World!");
            }
            ("POST", "/json") => {
                let body = req.body();
                let mut json: serde_json::Value = serde_json::from_slice(&body).unwrap();
                json["echo"] = serde_json::Value::String("received".into());
                res.status_code(200, "OK");
                res.body_vec(serde_json::to_vec(&json).unwrap());
            }
            ("GET", "/headers") => {
                // Echo back the custom headers
                let header_count = req.headers().len();
                let mut json = serde_json::Map::new();
                for h in req.headers() {
                    json.insert(h.name.to_string(), serde_json::Value::String(h.value.to_string()));
                }
                res.status_code(200, "OK");
                res.body_vec(serde_json::to_vec(&json).unwrap());
            }
            ("GET", "/not-found") => {
                res.status_code(404, "Not Found");
                res.body("404 Not Found");
            }
            ("GET", "/server-error") => {
                res.status_code(500, "Internal Server Error");
                res.body("500 Server Error");
            }
            _ => {
                res.status_code(404, "Not Found");
                res.body("Not Found");
            }
        }
    }
}

// Test: GET request with no body
#[test]
fn test_get_ok() {
    let server = HttpServer(TestHandler).start("127.0.0.1:0").unwrap();
    let client = HttpClient::connect("127.0.0.1", /* actual port */).unwrap();
    let response = client.get("/ok").send().unwrap();
    assert_eq!(response.status(), StatusCode::OK);
    assert_eq!(response.body(), b"Hello, World!");
    server.stop();
}

// Test: POST with JSON body
#[test]
fn test_post_json() {
    let server = HttpServer(TestHandler).start("127.0.0.1:0").unwrap();
    let client = HttpClient::connect("127.0.0.1", /* actual port */).unwrap();
    let obj = serde_json::json!({"key": "value"});
    let response = client.post("/json").json_body(&obj).send().unwrap();
    assert_eq!(response.status(), StatusCode::OK);
    let result: serde_json::Value = response.json().unwrap();
    assert_eq!(result["echo"].as_str().unwrap(), "received");
    server.stop();
}

// Test: Custom headers
#[test]
fn test_custom_headers() {
    let server = HttpServer(TestHandler).start("127.0.0.1:0").unwrap();
    let client = HttpClient::connect("127.0.0.1", /* actual port */).unwrap();
    let response = client.get("/headers")
        .header("X-Custom-1", "value1")
        .header("X-Custom-2", "value2")
        .send()
        .unwrap();
    assert_eq!(response.status(), StatusCode::OK);
    let headers: serde_json::Value = response.json().unwrap();
    assert!(headers["X-Custom-1"].is_string());
    server.stop();
}

// Test: Connection reuse
#[test]
fn test_connection_reuse() {
    let server = HttpServer(TestHandler).start("127.0.0.1:0").unwrap();
    let client = HttpClient::connect("127.0.0.1", /* actual port */).unwrap();
    
    // Send 10 GET requests — should all reuse the same connection
    for _ in 0..10 {
        let response = client.get("/ok").send().unwrap();
        assert_eq!(response.status(), StatusCode::OK);
    }
    // Verify only one connection was used (implementation-specific check)
    server.stop();
}

## Notes

- may_minihttp already has test infrastructure (`tests/test_server.rs`, `tests/simple_header_test.rs`). Reuse these patterns where possible.
- The mock server should run on a random port to avoid conflicts. may_minihttp's `HttpServer::start` returns the server handle — we need to discover the bound port.
- Integration tests require the `client` feature to be enabled (`--features client`).
- Consider: should integration tests use a real may_minihttp server (TCP) or an in-memory mock? TCP is more realistic but slower. In-memory is faster but doesn't test the actual network path.
